Parallel Ecommerce Ecosystem

Spring Boot 3.4 · Java 17 · PostgreSQL · Parallel Programming course (NFR #1–#5)

Balancer manager

● System running — you reached this page through the Spring Boot app .

Summary: E-commerce API with concurrency-safe checkout, async background tasks, nightly batch aggregation (Spring Batch), and Apache load balancing across two app instances. All five non-functional requirements are implemented and covered by automated tests.

Project at a glance (5 NFRs)

NFR #1Optimistic locking

@Version on Product + pessimistic lock at checkout. 50 concurrent users, stock=10 → exactly 10 orders, stock=0.

NFR #2HikariCP pool

Tuned maximum-pool-size (default 20). Larger pool → fewer waits under load.

NFR #3Async processing

@Async + ThreadPoolTaskExecutor + events after commit. Checkout ~212 ms while invoice/email run in background.

NFR #4Spring Batch

Daily sales ETL: 500k order items → 1k product summaries. Up to ~2,493 items/sec (chunk 100k).

NFR #5Load balancer

Apache Round Robin on :9999. Disable app1 in balancer-manager → traffic goes to app2.

Test class naming (JUnit 5)

Both *Test and *Tests are valid. This project uses Nfr{N}…Tests under nfr/ for NFR coverage, and descriptive names elsewhere (e.g. OrderServiceConcurrencyTests, DailySalesBatchJobTest). Maven discovers any public class whose name ends with Test or Tests.
